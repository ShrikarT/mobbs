## One numbered blocking finding batch

Line numbers refer to candidate `apps/api/app/budget.py`.

1. **P1 — invalid/excessive usage still discards representable known charge** (`:1170–1197`, `:1253–1274`; Spec, v2 usage/debt rules, matrix4 / G4). On a dispatched/received0.2225 reservation, settle `CanonicalUsage(input_tokens=2000000, output_tokens=0)` with the durable receipt. The API raises `BudgetUsageError` and commits pause/uncertainty, but a fresh connection reads charge/exposure **0.2225000000**, although the pinned uncached schedule implies the representable charge **2.5000000000**. Separately,500000 valid input tokens with inconsistent total1 leave0.2225 instead of retaining the calculable0.625 charge; `10**25` counts also retain only0.2225. Validation exits before computing any conservative known charge, leaving `calculated_charge=None`. The durable-transaction repair works, but the debt amount remains wrong. Expected fix: a bounded error-accounting path that preserves max(reservation, prior charge, representable known charge), including a defined safe maximum for overflow, while refusing normal settlement and retaining pause. Extend the huge-usage assertion beyond `charge >= reservation`. Reproduction/results: `controls.json` keys `over_context`, `bad_total_known_counts`, `huge`.

2. **P2 — canonical fingerprints and immutable billing evidence are incomplete** (`:337–365`, `:843–866`, `:1109–1130`, `:1213–1224`, `:1574–1585`; Spec, matrix2/6 / G2/G4). `record_receipt` with hashA/request_idA followed by hashA/request_idB returns idempotent success. Initial settlement replaces the received request_idA withB; settled replay with identical usage and request_idC also succeeds. Reconciliation replay accepts changed request IDs and even a nested private-marker dictionary without reaching the encoder; persisted evidence remains the original value, so this proves acceptance of conflicting/unvalidated replay rather than marker persistence. Both hash helpers use colon-joined strings and persist generic `fingerprint`, omitting the contract's sorted compact JSON representation and named `reservation_fingerprint_sha256` / `settlement_fingerprint_sha256`; the settlement digest omits billing IDs/model/status. Reservation compares digest **OR** a subset of fields: after changing only the synthetic row's persisted digest to64 `f` characters, exact reserve returns idempotent success despite the fingerprint mismatch. Expected fix: implement the pinned complete canonical fingerprints, validate complete evidence before every replay decision, require digest and all immutable fields to agree, and reject changed receipt/usage/billing identity with `BudgetConflict`. Keys `receipt_changed_metadata`, `initial_settle_changed_metadata`, `settle_changed_metadata`, `reconcile_replay_metadata`, `fingerprint_mismatch` supply minimal real-PG reproductions.

3. **P2 — retry admission permits cancellation and changed lease basis** (`:883–911`; Spec, v2 Retry and reconciliation rule, matrix2/5 / G2/G4). Reserve→cancel `user_cancelled`→reserve attempt1 immediately **succeeds**. v2 explicitly reserves attempt1 only after a recorded delayed `rate_limit_429`; cancellation is a separate safe transition. On another fixture, record429/Retry-After1, make the fixture rejection timestamp2 seconds old and advance its actual job generation; attempt1 with the new valid generation **succeeds**, even though the full immutable lease basis differs from attempt0. Expected fix: authoritative rate-limit category/delay checks and full prior reservation-fingerprint equality on retry; cancellation must not enter this retry gate. Preserve the passing400/403/account-denial refusal and attempt2 refusal. Keys `cancel_attempt1`, `retry_changed_generation`; timestamp adjustment is explicit fixture-only clock control, no wall-clock timing claim.

4. **P2 — final cancellation change breaks exact terminal replay** (`:1497–1502`; Spec, v2 cancellation exact-input replay rule, matrix2 / G2). Reserve, cancel with `user_cancelled`, then repeat the exact cancellation: **`BudgetStateError`**. Repeating with another valid reason `stage_closed` produces the same state error instead of `BudgetConflict`. Fresh DB state remains cancelled/zero charge with the original reason. Expected fix: validate and compare immutable cancellation evidence under account/attempt locks; return the original result for exact replay, conflict for changed evidence, and continue withholding sends/refunds for dispatched debt. `controls.json:cancel_replay`. This directly exercises the coordinator's final-revision hypothesis; passing committed suites do not contain this replay assertion.

5. **P2 — request parser admits duplicate keys and non-finite JSON** (`:761–774`; Spec, v2 Canonical input and quote, matrix1 / G2). Actual reserve accepts all three byte strings when their exact hashes are bound: duplicate `model` keys (`wrong` then pinned model), an extra `NaN` value, and an extra `Infinity` value. Each creates a persisted0.2225 reservation. Ordinary `json.loads` keeps the last duplicate and accepts these constants. Expected fix: strict object JSON parser rejecting duplicate keys and all non-finite constants throughout the request, before financial mutation. Existing model/output equality and exact-byte hash checks must remain. Keys `json_duplicate`, `json_nan`, `json_infinity`.

6. **P2 — financial encoder still violates its strict value grammar** (`:216–235`, `:242`, `:310–316`; Standards and Spec, shared bounded-input/privacy rule and v2 Financial evidence schema, matrix3 / G4/G5). Actual encoder accepts `request_id='req_28\n'` and a64-hex fingerprint followed by newline because regex `.match` with `$` accepts before the final newline. Actual receive and settle persist the newline identifier, and it survives real `request_deletion` + `delete_step`; fresh connection confirms run count0 and that exact invalid identifier in surviving financial JSON. The encoder also accepts binary float0.1, silently rounds a13-decimal money string, and permits an integer latency of `10**100`, violating finite Decimal/no-float and bounded evidence requirements. Expected fix: full-match identifiers/hashes, strict bounded per-field numeric grammar/ranges, reject unsupported precision/types rather than converting/rounding invalid evidence, and validate final merged evidence immediately before persistence. Keys `pure_encoder`, `deleted_newline_id`. Bool/NaN/nested/unknown-key rejection controls pass, and the synthetic private marker was **absent from persisted JSON**; this finding does not claim arbitrary prose or marker leakage was reproduced.

7. **P2 — uncertainty writer has no legal source-state gate** (`:1425–1463`; Spec, v2 explicit transition matrix / G3/G4). Settle a received unit at0.0021, then call `record_uncertain(attempt_id)` with defaults: it **succeeds**, rewrites the terminal settled unit to uncertain, increases stored charge/exposure to0.2225 and pauses the account. Source also applies the same unconditional transition to rejected/cancelled rows. v2 allows uncertainty from reserved/dispatched/received and monotonic recovery of existing uncertainty; terminal states must not regress. Expected fix: central legal transition checks with terminal conflict handling and exact recovery evidence semantics; preserve monotonic charge/receipt when the source state is legitimately unresolved. `controls.json:terminal_uncertainty` demonstrates the settled case; rejected/cancelled variants are source-visible, not separately executed.

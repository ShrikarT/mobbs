## One numbered correction batch

1. **P1 — Bind report facts to stored data and expose the stored methodology.** Criteria 2/3, A02/A07; `apps/web/src/App.tsx:330`, `:333`, `:457`, `:399`, `:479`. Observed B backend caveat says **0** unsupported notes, while UI says **1**. B's timeline heading ends at **3s** although media is 17.108s. A is 33.782s with no supported note, yet UI still draws four B segments ending 17.1s and labels 3–8s “Drop”; it omits the remaining A scenes. The UI displays interval endpoints without `completion.range.method`, `methodology.assumptions`, training-cutoff/source limitations or equivalent explanatory text, even with provenance open. Remedy: derive duration/scenes/triggers/suppression/cast facts from actual stored fields, show no supported trigger when absent, and make the recorded range method/assumptions/limitations inspectable. Add B and A browser assertions against actual stored values rather than current literals.

2. **P1 — Make terminal/error/processing/deletion states usable and recoverable.** Criteria 2/4/6; `apps/web/src/App.tsx:44`, `:68`, `:78`, `:271`, `:312`, `:541`. An actual production incomplete report with 2 effective/1 failed/0 pending and five events returns report HTTP200, but after seven seconds UI remains “Analyzing audience retention,” shows 50%, no report and **no buttons**. A valid unmatched silent upload shows only **Try again**, including after reload; no delete action exists. Processing also has no deletion action. Deletion pending was visible, but reloading returned to upload with no pending targets/status, since bootstrap lists only undeleted videos with runs. Remedy: handle complete/incomplete/failed/expired states explicitly, retain a deletion/recovery action for any accepted upload, surface terminal partial reports, and restore pending deletion from durable state across reload. Do not abandon retained resources via a state reset or silently swallow permanent 401/404 polling errors.

3. **P1 — Limit deletion language to demonstrated controlled copies.** Criterion 6/C8; `apps/web/src/App.tsx:516` and deletion UI/types. Actual completion headline is **“All data permanently removed”**; the backend explicitly says app-owned copies only and excludes historical source evidence/upstream backups. The UI never renders `DeletionState.caveat`. Remedy: render the stored scope/caveat during pending and completion and describe access revocation separately from deletion completion/session expiry. Do not claim permanent/upstream/all-source-data erasure. The independently observed 13/13 S3 absence supports app-owned cleanup only.

4. **P1 — Enforce idempotency binding on every successful path.** Criterion 5/C8; `apps/api/app/main.py:194`, `:241`, `:243`. Reproduction: create a run for owned B; POST it with a fresh key K (existing-run path returns202); reuse K with owned A → **202 creates/returns A's run, expected409**. Separately DELETE B using key D, then DELETE A using D → **202 and a different deletion ID, expected409**. The original creation key correctly returns409 for changed video and concurrent same-key creation returns one resource; the bypasses are specific to unrecorded existing-run responses and DELETE ignoring key binding. Remedy: bind the owner/route/key and canonical request identity transactionally for all returns, including existing resources and deletes, while preserving stable repeated deletion of one video across different keys. Add real HTTP regression tests for both counterexamples.

5. **P2 — Deliver persisted events and remove invented percentages.** Criteria 2/3/C4; `apps/web/src/App.tsx:92`, `:265`, `:282`; `apps/api/app/main.py:228`. The API emits named `persona.continued` / `persona.stopped` SSE events; UI subscribes only to `onmessage`, so a run with five stored events still says **“Awaiting scene checkpoints...”**. Upload shows fixed40%; stage percentages are fixed30/70/90 with fallback50, not stored measured progress. Remedy: subscribe to supported named event types, deduplicate/reconnect from persisted cursors, show actual persisted counts/stages, and use an honestly indeterminate indicator where progress is not measured. Observe a real mid-run/reconnect path in the regression.

6. **P2 — Complete the required accessibility behavior.** Criterion 2/A07; `apps/web/src/App.tsx:333`, `:558`; `apps/web/src/style.css:8`, `:56`, `:473`, `:647`. All four clickable timeline controls have tabIndex−1 and no role/keyboard handler; they cannot be reached as controls. Opening deletion by keyboard leaves focus on the background Delete button (observed `insideDialog=false`); no initial modal focus is established. Remedy: semantic keyboard-operable seek controls, correct dialog focus/keyboard lifecycle, compliant text contrast and a header that fits at 320px/zoom. The real note Enter-seek, trust Enter-expansion, no horizontal overflow at 320px and reduced-motion match did pass; these do not establish full AA or complete keyboard flow.
